_Tracking model: face landmarks (eyebrow ring, nose tip). Depends on the shared face-landmark engine — see [README.md](./README.md#shared-prerequisites-ye-pehle-banao--sabko-block-karte-hain)._

> **Per-subcategory tracker** — same convention [EYELINER.md](./EYELINER.md)/[KAJAL.md](./KAJAL.md)/[EYESHADOW.md](./EYESHADOW.md) established: as a subcategory gets built, it gets its own dedicated tracker file and [EYE.md](./EYE.md)'s own inline checklist for it gets replaced with a summary-row + link.

> **The first EYE finish built on a real, directly-tracked closed region**: EYELINER/KAJAL trace an open arc, EYESHADOW washes a _synthesized_ region (an offset of the lash line, since no crease landmark exists) - EYEBROW is the first one where MediaPipe already tracks the whole region directly as a closed ring (`LEFT/RIGHT_EYEBROW_INDICES`, the same points FACE's own full-face washes already use for their exclusion holes). 5 patterns: Bold/Defined Fill, Soft Powder Fill, and Ombre Brow are closed-region fills (flat, blurred, or gradient); Natural Hair-Stroke and Feathered/Fluffy draw many individual tapered strokes across the region instead, for a hair-like texture - procedural canvas math with deterministic per-stroke variation, not a texture image asset.

## Design notes

- **A real closed ring, not first/last-point ordering**: `LEFT/RIGHT_EYEBROW_INDICES` (10 points each) trace continuously around the brow's own physical loop - unlike the open eye arcs, where `orderInnerToOuter` decides which literal endpoint is inner vs outer, a ring's own first/last points are just wherever the index list happens to start/stop going around the loop, not necessarily either anatomical end. `findInnerOuterPoints` instead scans every point in the ring directly for whichever one sits closest to (inner) and farthest from (outer) the nose tip - correct regardless of how the ring's own indices happen to be ordered, needed for Ombre Brow's own gradient axis.
- **`traceEyebrowPath` - a closed-loop version of the same smoothing idea `smoothOpenPath` (EYELINER) already uses**: quadratic-curve-through-midpoints, wrapping back to the start instead of stopping at a real first/last point - the same technique FACE's own `traceSmoothClosedPath` (face.ts) uses for its own closed-ring regions, written fresh here per this file's self-contained-per-category convention rather than cross-imported.
- **Hair-strokes are procedural, not a texture asset**: `renderEyebrowHairStrokes` splits the 10-point ring into its two edges (first half/second half, the second reversed so both run the same rotational direction), smooths each into a dense point sequence, then for each of `strokeCount` strokes draws a single tapered segment (`fillTaperedPath`, the exact same ribbon primitive every other stroke-based EYE finish already uses) from a point on the lower edge to a point on the upper edge - comparing the two edge points' own y at render time (not trusting which constant array is "upper") to find which one is actually the base a hair grows from. `strokeJitter` (a deterministic sine-based hash, not `Math.random()`) varies each stroke's angle/length/width reproducibly, so the same photo always renders identically and this file's own smoke tests stay deterministic. `strokeAngleBiasDeg` blends each stroke's direction toward straight-up - 0 for Natural Hair-Stroke's own "lying along the brow's natural line" look, a much larger value for Feathered/Fluffy's "brushed up" soap-brow look - the only tuning difference between the two patterns.
- **Ombre Brow's gradient axis is the ring's own inner→outer line, not the eye's**: `ctx.createLinearGradient(inner.x, inner.y, outer.x, outer.y)` using the eyebrow ring's own `findInnerOuterPoints` result, lighter (`mixTowardWhite`) at the front/inner end, bolder (`mixTowardBlack`) at the tail/outer end - same per-channel math EYESHADOW already ported from FACE's own HIGHLIGHTER/CONTOUR.
- **Pattern-preview icons**: the 5 icons (`public/images/tryon/eye/eyebrow/*.webp`) reuse the same base template (light-gray lid-crease arc, gray iris + white highlight, thin black lash-line boundary) every other EYE finish's own icon set uses, generated with a one-off `canvas`-package Node script (not checked in, same temporary-tooling treatment as every other EYE finish's own icon generation), converted PNG→WebP via `cwebp`. A proper brow-arch shape (its own pair of quadratic curves, independent of the template's own decorative crease line) sits above the eye, styled per pattern - a neutral brunette tone for the 3 fill patterns, individual procedural hair-strokes (the exact same jitter/taper technique the real renderer uses, reimplemented for the icon script) for the other 2, which read as genuinely convincing individual-hair textures even at icon scale.
- **Verification done so far**: `tsc -b --force`, `eslint`, and the full `vitest` suite (95/95, including 7 new `applyEyebrowEye` smoke tests - all 5 patterns, one unrecognized-pattern-id case, and one EYELINER-id-cross-contamination case) all pass. Real-photo browser verification (North Indian model, Berry Wine, all 5 patterns): every pattern renders on both eyebrows following the real brow shape closely, with a visibly distinct look per pattern (Soft Powder's blur, Bold/Defined's crisp edges, Ombre's light-to-dark gradient, Natural Hair-Stroke's fine strand texture blending convincingly with the model's own real brow hairs, Feathered/Fluffy's more upward-brushed strokes) - and a pixel-diff between Bold/Defined Fill and Natural Hair-Stroke confirmed 7,705 genuinely changed pixels in the brow region.
