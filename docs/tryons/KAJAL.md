## Design notes

- **Exactly EYELINER ka apna primitive, bas ek alag arc**: `renderTaperedStrokeForEye` (`renderEyelinerForEye` se rename kiya gaya jab ye finish add hui) ko koi idea nahi hai ki kaunsi finish ise call kar rahi hai - ye bas jo bhi arc diya jaaye usko trace karta hai (`primaryArc`), `t` ke hisaab se width taper karta hai aur optionally blur karta hai, exactly EYELINER ke apne patterns jaisa. `applyKajalEye` `LEFT/RIGHT_EYE_LOWER_INDICES` ko `primaryArc` ki tarah pass karta hai (EYELINER upper arc pass karta hai); upper arc ko `secondaryArc` ki tarah pass kiya jaata hai sirf interface-shape consistency ke liye, kyunki `KAJAL_PATTERN_TUNING` kabhi `underlinerWidthRatio` set hi nahi karta aur wo parameter KAJAL ke liye kabhi read hi nahi hota. Ye dono finishes ke beech ka poora structural difference hai, [EYE-PLAN.md](./EYE-PLAN.md) ke apne build note se match karta hai ("shared primitive exist karne ke baad koi naya code nahi chahiye, sirf parameter tuning").
- **4 patterns, koi wing math nahi chahiye**: Thin Waterline aur Tightline Lower Lash wahi uniform-taper shape hain jo EYELINER ka Classic Thin/Tightline use karta hai, bas lower arc pe aur KAJAL-appropriate widths pe. Smudged/Smokey same `blurRatio` + `ctx.filter` blur pass reuse karta hai jo SMOKEY_SMUDGED (EYELINER) ne establish kiya tha. Full Bold Kohl ka "outer corner ke thoda paar extend karna" (per [EYE-PLAN.md](./EYE-PLAN.md) ki apni pattern description) akele ek wider `tipWidthRatio` se handle hota hai, `buildWingPoints` se nahi - kajal ka apna outer-corner extension EYELINER ke Winged/Double Wing se kaafi shorter, subtler flick hai, "line bas thick reh jaata hai bilkul end tak" ke itna kareeb ki ek real wing iske liye over-engineering hogi. `KAJAL_PATTERN_TUNING` ke 4 entries mein se koi bhi `wing`/`secondWing` set nahi karta.
- **EYELINER ke apne hard-won fixes free mein inherit karta hai**: kyunki ye _same_ `fillTaperedPath`/`outwardNormalsAlongPath` code hai jismein EYELINER ka apna gap/fragmentation bug fix hua tha ([EYELINER.md](./EYELINER.md) ke apne Design notes ka quad-decomposition fix dekho), KAJAL ko shuru se hi ye bug nahi tha - same flood-fill connected-component technique se re-verify kiya real photo pe jo EYELINER ki apni verification mein use hui thi (neeche dekho), sirf assume nahi kiya ki inheritance se "theek hona chahiye". Baad wale corner-fade-tail fix ke saath bhi same story hai ([EYELINER.md](./EYELINER.md) ke apne Design notes dekho) - `renderCornerFadeTail` unconditionally shared `renderTaperedStrokeForEye` ke andar call hota hai, isliye KAJAL ke apne non-winged patterns (sab 4 - KAJAL kabhi `buildWingPoints` use nahi karta) bhi ab waterline ke apne outer corner ke paar ek soft point tak taper karte hain, koi KAJAL-specific code change chahiye bina.
- **Pattern-preview icons, deliberately EYELINER ki visual language match karte hue**: 4 icons (`public/images/tryon/eye/kajal/*.webp`) exact same base template reuse karte hain jo EYELINER ke 7 icons use karte hain (light-gray lid-crease arc, gray iris + white highlight, thin black "unlined" reference line) - ek one-off `canvas`-package Node script se generate kiye (commit nahi kiya - isi "temporary tooling, shipped code nahi" treatment jo is session ke doosre diagnostic scripts ki hai), PNG→WebP `cwebp` se convert kiya (`node-canvas` ka apna `toBuffer('image/webp')` installed build me supported nahi hai). EYELINER ke icons se ek deliberate difference: bold product stroke _lower_ margin pe baithta hai upper ki jagah, taaki dono pattern pickers label padhe bina hi ek nazar mein visually distinguishable ho. Do bahut purani, alag-styled placeholder images (`Bold.webp`/`Classic.webp`) us folder mein pehle se hi baithi thi, ek earlier scaffolding pass se - in 4 se unrelated aur inse reuse nahi hoti - jagah pe hi rehne di gayi kyunki abhi koi unko reference nahi karta aur doosre pre-existing assets delete karna is task ka call nahi tha.
- **Ye finish add karte waqt ek real, pre-existing default-pattern gap fix hua**: `EyeEngineBase.applyEffect` ka pattern fallback pehle ek flat `state.pattern ?? EYELINER_DEFAULT_PATTERN` tha - jab tak EYELINER akeli pattern-bearing finish thi tab tak harmless tha, lekin jaise hi ek doosri finish apne alag id namespace ke saath exist karti (ek KAJAL selection jismein abhi koi pattern nahi choose hua tha silently EYELINER id se render karne ki koshish karta, `KAJAL_PATTERN_TUNING` mein kuch match nahi karta, blank render hota). Ek finish-keyed `EYE_DEFAULT_PATTERNS` map se fix kiya. Ek doosra, related gap: `TryOnModal` ka apna `initialState.pattern` `flow.engineState?.pattern ?? undefined` tha - waha ka comment claim karta tha ki ye `EyeEngineBase.getInitialState()` ke apne default pe fall back karta hai, lekin object-spread semantics aise kaam nahi karti (`{...base, pattern: undefined}` genuinely `undefined` hi rehta hai, `base.pattern` pe fall through nahi hota), isliye ek fresh session pe pattern picker mein _koi_ swatch selected nahi dikhta tha, jabki neeche engine ke apne fallback se kuch render ho raha hota tha. `TryOnModal` ko directly `EYE_DEFAULT_PATTERNS[tryOn.subCategory]` pe fall back karwa ke fix kiya, taaki picker ka "currently applied" swatch first frame se hi jo actually render ho raha hai usse match kare - live verify kiya (Thin Waterline apna check-circle/active border KAJAL kholte hi turant dikhata hai, picker ko touch kiye bina).
- **Ab tak ki verification**: `tsc -b --force`, `eslint`, aur poori `vitest` suite (80/80, 6 naye `applyKajalEye` smoke tests samet - sab 4 patterns, ek unrecognized-pattern-id case, aur ek EYELINER-id-cross-contamination case) sab pass hoti hai. Real-photo browser verification (North Indian model, Ruby Red, sab 4 patterns): lower-lash stroke dono eyes pe symmetrically render hota hai har pattern ke liye, Thin Waterline → Full Bold Kohl visibly thicken hota hai, aur Smudged/Smokey ke liye visibly soften hota hai; ek flood-fill connected-component scan (same technique jisse EYELINER ka apna wing-gap bug diagnose aur fix hua) ne exactly ek connected blob per eye paaya dono Thin Waterline (898px-scale default) aur Full Bold Kohl (1066px/1035px, left/right) ke liye - kisi bhi eye pe fragmentation nahi.
