# Try-On Feature — Master Tracker

Virtual tryon ko 5 main categories me build karna hai — **LIP, EYE, HAIR, FACE, NAIL** — har ek ke apne subcategories, aur har subcategory do modes me kaam kare.

- **Live mode** — webcam se real-time tryon
- **Upload mode** — user apni photo upload karke tryon dekh sake

Per-category detail aur checklist alag file me hai. Ye file sirf overall status aur un cheezon ke liye hai jo **sab categories ke liye common/shared** hai (ek baar ban gayi to sabko fayda).

## Test file convention (har category ke liye same)

Har category ke apne `src/utils/tryon-utils/<category>.ts` ke paas do alag test files hain, purpose se split - "kya cheez test ho rahi hai" se decide hota hai, "kaunsi category hai" se nahi:

- **`<category>.smoke.test.ts`** — canvas rendering tests (`apply<Finish><Category>` functions: "renders without throwing, paints pixels", color-math/placement assertions). `// @vitest-environment jsdom` + `import 'canvas'` chahiye (real Cairo-backed 2D context ke liye, jsdom akela kaafi nahi).
- **`<category>.test.ts`** — pure logic/data, koi canvas nahi (detection-status functions jaisे `isFaceTurnedTooMuch`/`isEyeTurnedTooMuch`/`getHairDetectionStatus`/`getHandDetectionStatus`, ya LIP ke `TEXTURED_FINISH_TUNING` jaisi constants validation). Default Node environment - koi jsdom/`canvas` overhead nahi chahiye.

Ye convention 2026-09-28 ko retroactively poori tarah enforce hua - HAIR/NAIL ke apne `getHairDetectionStatus`/`getHandDetectionStatus` tests pehle unke apne `.smoke.test.ts` files ke andar hi bundled the (LIP/FACE/EYE ke apne split se inconsistent), `hair.test.ts`/`nail.test.ts` mein nikal diye gaye. **Koi bhi naya category/finish add karte waqt isi split ko follow karo** - agar koi naya pure-logic helper (canvas na chahiye) add ho, uska apna test us category ke `.test.ts` mein jaaye, `.smoke.test.ts` mein nahi.

**Ek teesri, alag jagah bhi hai** - `src/constants/tryon-constants/<category>.test.ts` (`utils/tryon-utils/` se alag folder): sirf tab banta hai jab us category ka apna koi index-array constant genuinely **derived** ho (kisi doosre exported array se `.slice()`/`.reverse()`/spread se computed hota ho module-load time pe, hand-typed literal na ho) - jaisa LIP ka `LIP_OUTER_CONTOUR_INDICES` (`UPPER_LIP_INDICES`/`LOWER_LIP_INDICES` se derived) aur FACE ka `MOUTH_OUTER_CONTOUR_INDICES` (`MOUTH_UPPER_OUTER_ARC`/`MOUTH_LOWER_OUTER_ARC` se derived, same formula). Test exact expected numbers ko hardcode karta hai (usi formula se re-derive nahi karta - warna ek galat source-array edit bhi silently match kar jaata), taaki koi accidental edit source arrays ya derivation logic mein turant pakda jaaye. EYE/HAIR/NAIL ke apne constants files mein abhi koi aisa derived array nahi hai (sab hand-typed literals hain), isliye unke liye ye file zaroori nahi - **jis din koi naya derived constant kisi bhi category mein aaye, usko bhi yahi treatment milni chahiye**, sirf symmetry ke liye har category mein khali file mat banao.

## Suggested build order

1. **LIP** ✅ done — sabse simple region (single landmark ring), high product volume, sabse zyada learning yahi milegi baaki categories ke liye
2. **FACE** ✅ saari 8 subcategories poori tarah 10/10 hain (real-device QA bhi ho chuki hai, "sab sahi he") — same face-landmark engine reuse, thoda bada region set
3. **EYE** ✅ saari 7 subcategories poori tarah 10/10 hain (real-device QA bhi ho chuki hai, "sab sahi chal rha he")
4. **HAIR** ✅ saari 4 subcategories poori tarah 10/10 hain (real-device QA bhi ho chuki hai, "sab sahi chal rha he"). Segmentation-based (landmark nahi, poore strand ka `ImageSegmenter` confidence mask), shared `FaceLandmarkerEngineBase` reuse nahi hota, apna parallel `HairSegmenterEngineBase` chahiye pada - poori reasoning HAIR.md mein hai
5. **NAIL** ✅ saari 5 subcategories poori tarah 10/10 hain (real-device QA bhi ho chuki hai, "sab sahi chal rha he"). Naya tracking model (hand/finger, MediaPipe `HandLandmarker`) integrate kiya - poori reasoning NAIL.md mein hai (shared `FaceLandmarkerEngineBase` bhi reuse nahi hota, HAIR jaisa hi apna parallel engine chahiye pada, bas `HandLandmarker`'s sync detect ki wajah se utna divergent nahi)

## Progress kaise track karein

Har subcategory ke 8 checklist items hain — 4 Live mode ke, 4 Upload mode ke. `[ ]` ko `[x]` karo jaise-jaise kaam complete ho.

- **Subcategory %** = checked items / 8
- **Category %** = us category ke total checked items / total items (summary table upar hi bana hua hai har file me)
- **Overall %** = sabhi 280 items me se checked

Jab bhi kaam land ho, checklist update karo + is file ke summary table ka % bhi update karo (ya mujhe bol do, main recompute kar dunga).
