## Design notes

- **Why this needed genuinely new code, unlike every EYE finish before it**: EYELINER/KAJAL trace one continuous stroke along an arc; EYESHADOW washes a region; EYEBROW fills a closed region or draws hair-strokes across it. Mascara doesn't read as a continuous shape at all in real life - it's dozens of _individual_ lash hairs, each with its own root, its own curl, its own length - so the render needed to generate and fill many independent short curved shapes rather than one continuous path, which none of the earlier finishes' own primitives directly supported.
- **The lash curl is a rotating direction, not a Bezier bulge**: `buildLashPoints` walks `steps` short straight segments whose own direction rotates gradually from the lash's own root angle toward straight-up (`rotateTowardUp`) by `curlFraction` of the way there, rather than building one quadratic-curve bulge the way EYELINER's own wing (`buildWingPoints`) does. A rotating-direction walk is a more faithful model of how a real lash curls along its own length (increasingly upward from root to tip) than a single symmetric bulge would be, and reuses the exact "blend a direction toward absolute up" idea EYEBROW's own `strokeAngleBiasDeg` already established for its Feathered/Fluffy pattern - proven mirror-safe on both eyes there already, so no new mirror-safety risk here.
- **Each lash is still built from the same tapered-ribbon primitive every other stroke-based EYE finish shares**: once `buildLashPoints` produces the curved point sequence, `fillTaperedPath(tempCtx, lashPoints, center, (t) => width * (1 - t), color)` handles the actual fill - thick at the root, tapering to a fine point at the tip, the same gap-proof quad-decomposed ribbon technique EYELINER's own wing-gap fix established earlier this session. No new fill-robustness risk was introduced building this finish.
- **Root direction and Dramatic/Length's fan-out both come from the same mirror-safe machinery already proven for EYELINER/KAJAL**: each lash's root direction is the lash line's own `outwardNormalsAlongPath` value at that point (continuity-propagated, not per-point centroid-tested, avoiding the exact class of sign-flip bug EYELINER's own wing needed two iterations to fix) - `Dramatic/Length`'s own `fanOutDeg` then adds a small extra rotation to that root direction, scaled by both how far along the lash line the stroke sits and `horizontalSign` (the same mirror-safe "which literal direction is toward the outer corner" value EYELINER's wing already computes), so the fan sweeps toward the temple on both eyes correctly rather than a fixed screen-direction being right for only one side.
- **Deterministic per-lash variation, not `Math.random()`**: `strokeJitter` (already established for EYEBROW's own hair-strokes) varies each lash's own length/curl/width by a reproducible sine-based hash keyed on its index, so the same photo always renders pixel-identical mascara and this file's own smoke tests stay deterministic - real lashes are never perfectly uniform, and a mechanically identical repeat of one stroke shape would read as obviously synthetic.
- **Range bounds started pre-boosted, not discovered the hard way**: `EYE_RANGE_BOUNDS.MASCARA` (`{min:0.3,max:0.85,default:0.6}`) applied the "a thin individual stroke needs a boosted alpha range to actually read against real texture" lesson from the start, rather than shipping a soft placeholder and rediscovering the same lesson EYELINER/KAJAL/EYEBROW's own placeholders each needed real-photo testing to find.
- **Pattern-preview icons**: the 4 icons (`public/images/tryon/eye/mascara/*.webp`) reuse the same base template every other EYE finish's own icon set uses, generated with a one-off `canvas`-package Node script (not checked in, same temporary-tooling treatment as every other EYE finish's own icon generation) that reimplements `rotateTowardUp`/`buildLashPoints` directly so the preview is a faithful match for the real renderer's own output, not just an approximation.
- **Verification done so far**: `tsc -b --force`, `eslint`, and the full `vitest` suite (102/102, including 6 new `applyMascaraEye` smoke tests - all 4 patterns, one unrecognized-pattern-id case, and one EYELINER-id-cross-contamination case) all pass. Real-photo browser verification (North Indian model, Ruby Red, all 4 patterns): every pattern renders symmetrically on both eyes with a visibly distinct look (Natural's fine, sparse strokes; Volumizing's denser/thicker coverage; Dramatic/Length's longer strokes fanning out toward the outer corner; Curled's more pronounced upward bend at the tips) - and a pixel-diff between Natural and Volumizing found 1,689 genuinely changed pixels, confirming the pattern picker actually changes the render rather than just toggling UI state.
